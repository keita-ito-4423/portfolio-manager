# トレード履歴管理ツール 要件定義書

- **対象**: 投資ポートフォリオ／トレード履歴管理ツール
- **作成日**: 2026-03-12
- **版数**: Ver. 0.1（調査結果を踏まえた初版）

> 文書の目的：公開リポジトリ調査で確認できた実装トレンドを踏まえ、マルチアセット対応のトレード履歴管理ツールの要求事項を整理する。  
> 対象ユーザー：個人投資家／複数口座・複数資産を横断管理したいユーザー。  
> 今回の前提：売買入力、履歴管理、損益計算、複数ポートフォリオ管理をMVPの中核とし、自動連携は段階導入とする。

## 1. 背景と目的

既存の公開ポートフォリオ管理ツールを確認すると、複数ポートフォリオ管理、複数資産種別の横断管理、取引履歴の蓄積、CSV import/export、価格同期、損益分析が共通の中核機能として位置付けられていた。本ツールでは、これらのうち特に**「手入力しやすいトレード履歴管理」**と**「後から分析しやすいデータ構造」**を重視する。

また、将来的には市場価格の自動取得、投資判断メモ、税務・確定申告補助、バックテストとの接続などへ拡張できる設計を前提とする。

## 2. スコープ

### 2.1 対象範囲（In Scope）

- 株式、ETF、投資信託相当、暗号資産、金・銀等のコモディティを同一ツールで管理する。
- 複数ポートフォリオを作成し、ポートフォリオ単位・全体単位の残高と損益を確認する。
- 売買、入出金、手数料、配当・分配金、スプリット、資産振替などの履歴を記録する。
- 取引履歴から平均取得単価、実現損益、評価損益、保有数量、キャッシュ残高を算出する。
- CSV import/export と履歴検索・絞り込みを提供する。
- 将来の価格データ連携・ブローカー連携を見据えた拡張可能なデータモデルとする。

### 2.2 対象外（Out of Scope）

- 証券会社・取引所への自動発注機能
- 高頻度取引用のリアルタイム注文管理
- 法人会計や複式簿記の完全対応
- 税務申告書の自動作成そのもの

## 3. 想定ユーザーと利用シナリオ

### 個人投資家

- 複数口座・複数資産を保有する。
- 手入力、CSV取込、損益確認を行う。
- 一元管理と履歴蓄積を期待する。

### 短中期トレーダー

- 売買回数が多い。
- 履歴検索、銘柄別分析、期間集計を行う。
- 振り返りと改善を期待する。

### 長期投資家

- 積立・配当・リバランスを重視する。
- 定期取引登録、配当記録、目標配分確認を行う。
- 資産推移の可視化を期待する。

## 4. 業務要件

- ユーザーは任意の数のポートフォリオを作成できること。
- 各ポートフォリオは複数の口座・ウォレット・保管先を持てること。
- 1つの資産は複数ポートフォリオに別建てで保有できること。
- 取引入力は「あとで分析できる粒度」を優先し、約定日、受渡日、数量、単価、手数料、税金、通貨、メモを保持すること。
- 損益計算は少なくとも平均法とFIFOのいずれかを実装し、将来方式追加が可能であること。
- 価格未取得の資産でも手動時価入力により評価額を出せること。
- 全履歴は監査可能であり、編集・取消の痕跡を保持できること。

## 5. 機能要件

### 5.1 ポートフォリオ管理

- ポートフォリオの作成、更新、アーカイブ、表示順変更
- ポートフォリオごとの基準通貨設定
- ポートフォリオ横断集計（総資産、実現損益、評価損益、資産配分）

### 5.2 資産マスタ管理

- 資産種別：株式、ETF、投資信託相当、暗号資産、コモディティ、現金、その他
- 識別子：ティッカー、ISIN/任意コード、取引所、通貨、表示名
- 価格ソース：自動取得／手動入力／未設定
- 無上場資産や価格未連携資産も登録可能

### 5.3 取引履歴管理

#### BUY
- 必須入力：日付、資産、数量、価格、手数料
- 計算影響：数量増、取得原価増、キャッシュ減
- 備考：現物買い
- 優先度：高

#### SELL
- 必須入力：日付、資産、数量、価格、手数料
- 計算影響：数量減、実現損益、キャッシュ増
- 備考：現物売り
- 優先度：高

#### CASH_IN / CASH_OUT
- 必須入力：日付、金額、通貨
- 計算影響：キャッシュ増減
- 備考：入出金
- 優先度：高

#### FEE / TAX
- 必須入力：日付、金額、通貨
- 計算影響：コスト計上
- 備考：単独費用
- 優先度：中

#### DIVIDEND / INTEREST
- 必須入力：日付、金額、通貨
- 計算影響：インカム増
- 備考：配当・利息
- 優先度：中

#### TRANSFER
- 必須入力：日付、移動元、移動先、数量/金額
- 計算影響：保管先変更
- 備考：ポートフォリオ内外の振替
- 優先度：中

#### SPLIT / MERGE
- 必須入力：日付、対象資産、比率
- 計算影響：数量・単価再計算
- 備考：株式分割等
- 優先度：低

### 5.4 損益・分析

- 保有数量、平均取得単価、簿価、時価、評価損益、実現損益を銘柄別に算出する。
- 日次・週次・月次・年次・任意期間の損益推移を表示する。
- ポートフォリオ別、資産種別別、通貨別の集計を行う。
- 手数料込み損益を標準とし、手数料除外表示は補助表示とする。
- 将来拡張として TWR/IRR、配当利回り、リバランス乖離率を追加可能とする。

### 5.5 検索・フィルタ・エクスポート

- 履歴一覧で日付範囲、ポートフォリオ、口座、資産種別、銘柄、取引区分、タグで絞り込めること。
- CSVエクスポートは元履歴の再現に十分な粒度を持つこと。
- CSVインポート時はプレビュー、バリデーション、エラー行表示、重複検知を行うこと。

### 5.6 メモ・ジャーナル（推奨）

- 取引ごとに任意メモ、タグ、戦略名、根拠を紐づけられること。
- 将来的に投資判断ログ・トレード日誌の分析に使える構造とする。

## 7. データ要件

### 7.1 主要エンティティ

- User：利用者
- Portfolio：ポートフォリオ
- Account：証券口座、取引所口座、ウォレット、現金口座
- AssetMaster：資産定義
- Transaction：取引履歴本体
- PositionSnapshot：日次または都度計算された保有・評価スナップショット
- PriceHistory：価格履歴
- FxRateHistory：為替履歴
- Tag / Note：分類・メモ

### 7.2 Transaction の必須属性

- `transaction_id`, `portfolio_id`, `account_id`, `asset_id`
- `transaction_type`, `trade_date`, `settlement_date`
- `quantity`, `unit_price`, `gross_amount`, `fee_amount`, `tax_amount`, `currency`
- `fx_rate_to_base`, `memo`, `source_type(manual/import/api)`, `source_file`, `created_at`, `updated_at`

### 7.3 計算ルール方針

- 保有数量は取引履歴の逐次適用により算出する。
- 実現損益は売却時に計算し、評価損益は最新価格で再計算する。
- 通貨換算は取引日時点レートと評価日時点レートを区別する。
- 編集・取消時は再計算の整合性が保たれること。

## 8. 非機能要件

| 分類 | 要件 | 目標/補足 |
|---|---|---|
| 性能 | 10万件程度の履歴でも主要画面が実用速度で表示されること | 一覧初期表示3秒以内を目安 |
| 信頼性 | 再計算結果が再現可能であること | 計算ロジックのテスト必須 |
| 可用性 | ローカル／セルフホスト前提でも継続利用しやすいこと | バックアップとエクスポート |
| 保守性 | 資産種別や取引区分の追加が容易であること | 疎結合なドメイン設計 |
| セキュリティ | 個人資産データを安全に保持すること | 認証、暗号化、監査ログ |
| 拡張性 | 価格APIやブローカー連携を将来追加できること | 連携層を抽象化 |

## 9. MVP定義

- **MVP-1**：複数ポートフォリオ、資産マスタ、手動取引登録、履歴一覧、保有・損益計算
- **MVP-2**：CSV import/export、価格手動更新、基本分析画面
- **MVP-3**：価格自動取得、為替レート連携、配当・振替・分割対応
- **将来拡張**：ブローカーAPI連携、トレードジャーナル分析、税務補助、通知

## 10. 受入基準（抜粋）

- 同一銘柄を複数ポートフォリオで保有しても混線せず集計できること。
- BUY / SELL / CASH_IN / CASH_OUT の登録・編集・削除ができ、再計算結果が正しいこと。
- CSVインポートでエラー行を特定できること。
- 履歴から銘柄別の実現損益と評価損益を確認できること。
- 基準通貨が異なる資産を1つのポートフォリオ内で集計できること。

## 11. 設計上の推奨方針

- 「ポジションを直接更新する」のではなく、「取引履歴から導出する」モデルを採用する。
- 価格取得失敗時でもツール利用が止まらないよう、価格取得は補助機能として分離する。
- UIはダッシュボード先行ではなく、履歴入力と履歴品質を最優先にする。
- 外部連携ごとに import adapter を分離し、CSV / 証券会社 / 暗号資産取引所の差分を吸収する。

## 12. 参考調査サマリ

公開リポジトリ調査では、以下の傾向が確認できた。

- **Ghostfolio**：トランザクションの作成・更新・削除、マルチアカウント管理、取引の import / export を提供。
- **Wealthfolio**：複数アカウント・複数資産、アクティビティ管理、ローカルデータ、アドオン拡張性を重視。
- **Assets**：複数ポートフォリオ、CSV import、取引単位の影響分析を提供。
- **Finanze / Road To FIRE**：株式・暗号資産・コモディティ等のマルチアセット、複数通貨、履歴管理を重視。

> ※ 本要件定義は上記の共通機能を踏まえつつ、トレード履歴管理に焦点を当てて再構成した。
